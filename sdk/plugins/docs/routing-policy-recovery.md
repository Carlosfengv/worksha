# 策略范围核查与恢复

模型服务页中的“核查策略范围与恢复”是宿主入口，不依赖策略插件启用、发布者当前信任或 worker 正常运行。先读取范围，再核查选中服务。原服务、已删除服务的范围记录和仍待核查的原发布均可列出；部分目录不可读时明确显示缺口。

服务标识保持原始字符串，包括旧代码接受的大小写、URN、花括号及无连字符 UUID。不会通过改写标识来合并范围；同一 UUID 的不同历史字符串范围需要逐一核查，尚未核查的范围继续受到保护。

- **确认使用内置策略**：仅在没有未解决发布、范围身份可核对时开放。保存原控制记录及必需标记的备份，然后写入新的解除状态。原服务配置、版本绑定和发布历史保留；旧授权身份退役。在途请求仍由原执行者处理。
- **解除遗留策略要求**：服务当前不存在时，明确解除残留要求，包括两份记录仍一致的已删除服务范围。保留删除状态、绑定与发布历史，不创建服务或提交原发布；解除后不能重复生成新的恢复记录。
- **恢复原编号核查入口**：仅在唯一原发布、原请求和此前范围证据可核对时开放。恢复同一 operationId 的 pending 屏障及原请求摘要；不提交发布，不调用模型，不恢复插件授权。之后通过原发布列表明确核查、继续或取消。

确认窗口展示服务和宿主核查编号。证据改变或核查超过 60 秒后，重新核查才能确认。保存结果不明时窗口保留原编号，用户可明确选择“核查并完成本次恢复”；此动作只完成同一份已保存收据，不覆盖后续选择，不生成新发布编号。

可恢复情况包括有残存版本绑定的控制行和标记同时丢失、可确认的原 pending 范围，以及已删除服务留下的可辨认标记。此前明确解除或取消的 revision 需要原控制记录或唯一对应绑定作为证据。无法核对的旧 head、多条未解决发布、损坏的原请求、整库丢失、库文件身份替换、未知未来格式及超过核查容量等继续保持未知；从备份核对原文件，不提供强制清空或猜测恢复。

核查不创建可选策略仓储。显式恢复在独立策略库中将备份收据和控制记录共同提交，之后同步必需标记；主库 schema 15、策略格式 1 和原表记录保持。收据上限 256，不自动删除历史腾出容量。范围 256 个满额时，同一未知范围可使用原预留名额恢复；新范围仍拒绝。发布意图满额时应保留原编号查询、取消和终态返回能力。

原数据与主服务业务操作仍由原仓储和操作发布器负责。该入口不提供任意文件、SQL、凭据、网络或 guest 调用权限。DSH、真实 Keychain 专项、Developer ID 与正式公证继续未验证。
