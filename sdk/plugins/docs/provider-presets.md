# 统一供应商预设（宿主契约）

`provider-adapter` 的静态预设部分由同一 `PresetAdapter` 只读契约提供：内置实现复用现有 `resources/provider-catalog.json`，外部实现桥接签名 manifest 的 `providers`。目录请求 / 解析与验证仍使用原 ProviderAdapter 边界，配置规划使用 ConfigPlanner；静态预设本身不携带执行能力。

新宿主命令 `query_provider_presets(input)` 提供 `list / resolve`，使用当前 `storeId`。四份严格 schema 和 TypeScript 位于 `contracts/domain/provider-presets/`，CLI 导出命令为 `schemas-provider-presets`。该接口只复制预设，不授予 guest 额外调用权限。

| 操作      | 行为                                                           | 身份                                             |
| --------- | -------------------------------------------------------------- | ------------------------------------------------ |
| `list`    | 列出完整、有界的候选及逐来源错误；不执行插件或批量校验归档正文 | 内置 presetId；外部 pluginId + digest + presetId |
| `resolve` | 选择时核查当前启用版本、信任与实际签名内容，再返回可编辑初始值 | 回应必须与原选择和数据库完全一致                 |

回复只包含名称、来源、基础协议、预设地址、初始模型及内置文档链接。外部模板使用 `vendor=custom` 进入原编辑器，不把外部 ID 伪装为内置供应商，也不把插件 / 模板 ID 写进原 Provider ID。相同名称和模板 ID 通过结构化来源区分。原 8 个内置预设、顺序、地址和文档保持。

## 现有包兼容

已安装、启用的 `provider.catalog@1` 包无需重打包即可出现在统一选择器。候选从已安装元数据读取，选择时以实际签名包为准；损坏的单个来源保持错误，不隐藏其他健康来源和内置预设。全局安装上限仍为 64 包，每包最多 16 个预设；一次完整读取最多 1032 个候选，回复最多 4 MiB。超量或不完整数据明确失败，不把当前页当作全量。界面搜索完整集合，每次最多显示 200 项。

原插件页 `create-provider` 行为、稳定映射、返回格式和旧数据库表保持；其模板转换复用同一适配器。新 `list / resolve` 不分配 Provider 映射、不保存连接，不推进原 Provider 操作序号或读写凭据。原生插件页的旧创建入口仍可使用。

## 编辑与权限

统一选择器仅复制初始值。用户已有自定义名称、服务地址、模型和凭据引用按原编辑规则保留；空草稿可以采用模板初始模型。自动生成的凭据名称遵守原 200 UTF-8 字节限制，供应商名称保持原文。

选择不读取 Key、不创建凭据、不授权目录、不获取模型或验证连接。目录来源及授权继续单独选择。新 Key 仍直接进入原准备 / 保存流程，不增加新的确认步骤；旧凭据恢复、未知结果和原恢复信封不变。预设不能使外部目录权限延续到已保存连接。

核查预设期间暂停修改和业务提交，可以关闭窗口。关闭、后台重连、数据库切换、能力状态变化或草稿已改变时，迟到回复不能覆盖输入。已复制内容可独立编辑；来源后来停用或撤信不会偷偷改写草稿，也不会把它改选为内置模板。重新选择须重新核查。已经保存的连接继续由原 Provider / 目录来源 / 协议绑定及恢复契约管理。

预设是静态初始值；插件启用状态允许其重启后继续可见，静态复制不等于恢复网络授权。目录 / 协议权限仍按原实例与修订失效。可选外部元数据服务不可读时，内置预设保留并明确显示外部来源待核查；没有将未知外部来源自动替换成内置来源。
