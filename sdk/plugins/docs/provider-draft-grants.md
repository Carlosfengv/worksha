# 编辑器目录授权生命周期（宿主接口）

此接口由宿主编辑器与恢复流程使用，不提供给 guest，不增加插件权限。
原 `provider.models@1`、目录 binding / selection、原 Provider 操作及已有 IPC 保持。
新增 `perform_provider_draft_grant(input)`，schema 位于
`contracts/domain/provider-draft-grant/`，SDK 导出命令为
`schemas-provider-draft-grant`。

## 流程与边界

1. 用户明确选择目录、当前连接范围和私有网络选项。
2. `open` 核对范围并生成宿主归属 ID；只保存无权限的准备记录。
   准备记录没有 binding，不能读取目录。丢失回复也不会留下未归属的网络授权。
3. 编辑器完整保存归属后才发送 `acquire`。宿主先保存包含精确 nonce 的意图，
   再发布授权，最后确认。回复丢失时使用同一个归属 ID 核查；不根据列表差异猜测归属。
4. 读取仍使用原宿主 Draft 目录接口，复核原 Saved / New、来源、当前范围与授权。
   归属记录本身不能替代权限检查，也不自动成为 Saved 授权。
5. 保存前先在本机归属记录中关联原 operationId，再保存原恢复信封；失败则不提交。
   `attach` 将原请求的宿主规范编码摘要、来源令牌和精确 selection 固定到归属。
   它不创建业务操作、访问 Vault、读取目录或发送模型请求。
6. 原提交 / 查询 / 重试 / 取消继续使用原请求、编号和来源契约。
   `pending`、未查到原结果、回执不明及不可读取恢复记录均保留授权。
   关闭未知结果的编辑器仍保留原请求和授权，不自动再次提交。
7. 原结果确认进入提交 / 失败 / 取消终态后，任一正常恢复视图可请求 `release`。
   宿主核对原数据库、完整请求摘要和实际 SQL 结果；仍有相关在途操作时保留授权。
   已关闭且有可靠归属的空闲授权可直接释放。释放不修改 Provider 或原回执。

`open / acquire / attach / release` 都是有限宿主管理操作。
它们不调用 guest、目录、模型或 Vault，不推进 Provider SQL 写入序号。
普通元数据读取和目录读取均不会新增归属或重新授权。

## 复用与回收

- `prepared`：尚无授权；`acquired`：持有宿主管理的精确授权引用；
  `borrowed`：借用既有或由旧入口复用的授权，不能自动删除；
  `pending`：原操作仍需核查；`released`：此归属已结束。
- 两个宿主编辑器复用同一个新建授权时分别保存引用。
  首个结束只释放自身引用，最后一个结束才可删除精确授权。
- 原有授权不会被接管。旧入口明确复用一个新建授权后，宿主将其保留为共享授权，
  原编辑器不能自动删除；用户仍可通过原插件管理入口明确解除。
- 回收比较完整 binding nonce 与原记录。授权被更新或替换后，旧归属不能删除新授权。
- 已删除归属的迟到 `acquire` 返回不存在，不能重新创建授权。
  新 `open` 总是生成新的宿主 ID；调用方不能指定或复活已结束的归属。
- 用户撤权后重新明确同意时，编辑器结束旧的空闲归属并准备新归属；
  不重复使用已经撤销的授权，也不在普通读取或后台重连时自动续期。
- 重启不恢复目录权限。保留的原归属仍可在原数据库核查并结束。
  撤权、停用或卸载后的业务结果查询和取消继续由宿主管理。

## 持久化与故障

原目录授权文件格式保持。新增宿主私有 `draft-catalog-owners` 目录只保存
受保护范围、引用及请求摘要，不保存原始 Key 或完整 Provider 请求。
单条不超过 32 KiB，最多 128 个归属；与原 128 个目录 binding 预算分别核查，
不能利用多个归属增加目录授权上限。没有产生授权的准备记录可在过期或重启后回收；
含授权或待核查请求的记录不会按时间自动删除。

前端使用独立的版本化恢复键，不改原 Provider 恢复信封。
归属存储失败时不会继续申请授权；已知空闲专属授权关闭时可由宿主结束，
不会因本机提示写入不足而永久保留。无法证明归属时保留记录，不猜测并撤销其他授权。
授权已固定到原请求后，即使首次业务提交明确返回容量等准入拒绝，也保留原恢复提示；
原结果缺失不等于可回收，用户可核查或取消同一个原操作，确认终态后再结束归属。

独立恢复增量在不改变此小记录格式的前提下，另保存受保护的完整请求副本；
具体接口、手动核查界面与旧版限制见 [草稿授权独立恢复](provider-draft-recovery.md)。
不声明全自动回收、正式性能或实际旧版本数据回退已验收。
DSH、真实 Keychain 专项、Developer ID 和正式公证保持未验证。
