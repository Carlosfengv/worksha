# 数据归属与持久化边界

插件中心统一安装来源和管理操作。物理存储按事务、恢复和访问边界组织；业务插件通过宿主领域接口访问共享数据。上传 Wasm 没有 SQLite、任意文件或凭据读取接口，不能提交 SQL、迁移脚本或表名。

## 存储目录

以下路径相对于应用数据目录。表的 SQL 与 Rust 读写器是实际格式的权威来源。

| 存储                           | 所有者及内容                                                                                           | 格式与保留规则                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `local-agent.sqlite3`          | 宿主管理系统插件状态、来源授权、设置与操作回执；Provider、模型服务、路由及凭据恢复元数据由对应领域管理 | `user_version=16`；业务停用、卸载不删除共享配置、历史版本和恢复材料                      |
| `plugin-host.sqlite3`          | 上传包、发布者信任、版本选择、来源/连接授权、按包摘要保存的设置、安装日志                              | `host_version=1`；卸载回收受管包，保留配置及审计；重装不恢复已撤销授权                   |
| `plugin-extensions.sqlite3`    | 扩展资源引用、协议绑定、配置计划与恢复证据、连接器调用记录                                             | `extension_version=1`；有备份或结果待核查的计划按原恢复规则保留；调用记录有界            |
| `plugin-source-host.sqlite3`   | 来源包、版本选择、授权状态、持久投影、项目隐藏记录                                                     | `full_version=1`；撤权与版本状态在同库提交并清理派生投影；运行中的来源授权不靠重启恢复   |
| `domain-host.sqlite3`          | 统一领域读取的明确同意和来源投影                                                                       | `domain_version=1`；授权变更与投影失效同事务；未使用时不创建                             |
| `routing-policy.sqlite3`       | 策略包、选择、服务范围控制、版本绑定、发布意图与恢复收据                                               | `policy_meta.format=1`；范围与主库 `storeId` 绑定，不能用缺失或损坏记录推断原生路由可用  |
| `object-contributions.sqlite3` | 对象摘要的插件/插槽授权                                                                                | `user_version=1`；绑定当前仓库及原插件库的文件身份，不与其他对象共享授权                 |
| `observations.sqlite3`         | 本地请求历史、内容失效标记及留存事实                                                                   | 独立内容格式；持久历史和事实不能作为插件缓存删除；查询视图、冻结快照和导出引用由宿主回收 |
| `workbench/tasks.sqlite3`      | 任务、原生会话关联、共享会话记录和操作回执                                                             | 独立格式版本与仓库身份。中断任务恢复为待核查。任务插件卸载保留记录                       |

数据目录中的配置备份、插件受管包、选中标记、授权文件与系统钥匙串不属于 SQLite 联合事务。系统钥匙串中的凭据不复制到插件库，也不返回界面。原生 Agent 来源目录属于用户，插件卸载不能删除它。

## 系统插件状态与升级

`builtin_plugin_composition` 是单例期望状态，保存格式版本、单调修订、内部服务入口以及停用/移除标识。`builtin_plugin_operations` 以操作 UUID 唯一记录原请求及回执，绑定主库持久身份；同一操作编号更换参数会被拒绝。实际运行代在内存中发布，不能把已保存的期望状态当作运行成功。

状态、相关本机来源授权撤销和回执在同一 `BEGIN IMMEDIATE` 事务提交。准备、健康检查或持久化失败保留上一运行代；提交后中断通过原回执和重启时的期望状态恢复。资源回收失败则关闭业务准入并保留恢复状态。

版本 15 升级前以 `VACUUM INTO` 创建 `local-agent.pre-plugin-lifecycle-v15.sqlite3`，核对完整性、原版本和私有文件权限。插件表、初始单例与版本 16 屏障一起提交；已有 P1 插件状态及凭据、Provider、授权、回执的原始行保持。旧版应用在任何业务读取前拒绝版本 16，避免忽略停用状态。

新库持久保存修订 0 的初始单例。未发生变更时，桌面/后台入口决定默认服务配置；首次变更后使用明确保存的配置。当前格式下缺表、单例丢失或未知记录格式均明确失败，不重建空状态，不自动全部启用。历史格式仅在明确迁移路径内允许初始化。

## 上传插件仓库

固定宿主表及格式标记在一个事务内初始化。初始化前检查格式标记和所需表；未来版本、重复/空格式标记、缺表以及其他用途的数据库均保留并拒绝使用。首次建表失败回滚后允许重试，不把部分建表解释为安装成功。可选仓库异常不授予插件能力；独立仓库保持原有可用性。可选扩展的临时锁失败允许再次读取，不永久缓存首次错误。

安装包使用摘要、版本和发布者身份校验。数据库提交与包文件、选中标记的发布由现有安装日志和启动核查协调；回执/标记不能证明授权仍有效。来源与连接读取仍检查当前摘要、授权修订、运行代和资源身份。

## 容量、回执与恢复

系统插件最近 256 笔回执有界保留。界面另行保留结果未知的原请求；查不到回执仅表示当前保留范围内没有记录，不能宣称从未执行。过期请求的旧修订不能重新生效，界面不自动重放写入。其他领域继续使用各自的容量、取消围栏和恢复规则，不能为了腾出空间删除待核查证据。

缓存回收只处理归属该能力的派生视图、临时结果与受管副本。历史请求、任务、用户配置、原始来源、凭据恢复材料和审计数据均按各自保留规则处理。插件代码版本、数据库格式版本、授权修订及运行代分别校验。

运行中的 WAL 数据库通过 SQLite 一致快照备份，不能只复制主文件。跨库恢复需要在服务停止、无写入时收集同一批数据库及相应恢复文件，核对完整性和主库身份；不能混用不同备份批次的授权、标记和业务版本。当前没有面向用户的整套多库备份/恢复产品流程，不能将单库迁移备份描述为完整备份。

工作台从无版本格式升级时，先生成只允许当前用户访问的 `tasks.pre-v1.<编号>.sqlite3` 一致性备份。备份包含已提交 WAL 数据，升级不改写旧任务和共享会话行。仓库身份、回执表与格式标记在同一事务写入。更新版本或结构不完整时停止打开工作台。恢复旧格式备份时，先正常退出使用该仓库的应用，再在独立目录验证备份。恢复点之后的记录保存在原仓库，可单独核查。

任务创建和本地发送把任务版本与接收回执同时提交。工作台保存 Agent 产品、数据来源、连接身份和实现版本，沿用原任务及原生会话编号。桌面写入复核仓库身份与插件授权代次，发送同时复核任务版本。共享服务在提交前保存待核查记录，以原生会话和消息证据确认丢失的响应。旧共享接口缺少可核实的消息编号时，结果保持待核查。

上传插件通用私有存储的配额、迁移协议与按插件清理接口须随相应 SDK 能力实现。当前上传接口开放已实现的宿主数据操作。
