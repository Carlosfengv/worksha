# 数据归属与持久化边界

插件中心统一安装来源和管理操作。物理存储按事务、恢复和访问边界组织；业务插件通过宿主领域接口访问共享数据。上传 Wasm 没有 SQLite、任意文件或凭据读取接口，不能提交 SQL、迁移脚本或表名。

## 存储目录

以下路径相对于应用数据目录。表的 SQL 与 Rust 读写器是实际格式的权威来源。

| 存储                      | 所有者及内容                                                                          | 格式与保留规则                                                                              |
| ------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `local-agent.sqlite3`     | 系统插件状态、来源授权、设置、操作回执、IAM、Provider、模型服务、路由及凭据恢复元数据 | IAM 关闭时 `user_version=18`，开启时为 19。业务停用和卸载保留共享配置、历史版本和恢复材料。 |
| `ext_host_*`（主库）      | 上传包、发布者信任、版本选择、来源与连接授权、插件设置、安装日志                      | 卸载回收受管包。重装需要重新授予已撤销的授权。                                              |
| `ext_adv_*`（主库）       | 扩展资源、协议扩展、配置计划与恢复证据、连接器调用                                    | 保留带备份或待核查的计划。连接器调用最多保留 10,000 行，留存预览从主库读取。                |
| `ext_source_*`（主库）    | 完整来源包、版本选择、授权状态、持久投影、项目隐藏记录                                | 撤权与版本状态同事务更新，并清理派生投影。                                                  |
| `ext_domain_*`（主库）    | 统一领域读取同意与来源投影                                                            | 授权变更与投影失效同事务提交。                                                              |
| `ext_policy_*`（主库）    | 策略包、版本绑定、发布意图、服务范围控制与恢复回执                                    | 范围绑定主库 `storeId`。缺失关键证据时保留待核查状态。                                      |
| `ext_obj_*`（主库）       | 对象摘要的插件与插槽授权                                                              | 授权绑定主库文件身份。                                                                      |
| `observations.sqlite3`    | 本地请求历史、内容失效标记及留存事实                                                  | 独立内容格式；持久历史和事实不能作为插件缓存删除；查询视图、冻结快照和导出引用由宿主回收    |
| `workbench/tasks.sqlite3` | 任务、原生会话关联、共享会话记录和操作回执                                            | 独立格式版本与仓库身份。中断任务恢复为待核查。任务插件卸载保留记录                          |

数据目录中的配置备份、插件受管包、选中标记、授权文件与系统钥匙串不属于 SQLite 联合事务。系统钥匙串中的凭据不复制到插件库，也不返回界面。原生 Agent 来源目录属于用户，插件卸载不能删除它。

## 本机连接、预算与熔断

`gateway_chat_keys` 保存授权绑定和当前 Key 版本及摘要，`gateway_chat_operations` 保存创建、轮换、撤销与交付回执。原生连接文件可核对后再完成同一次待激活操作。Key 明文由桌面原生层生成并写入用户选定的 `0600` 文件，管理接口只返回非敏感状态。

`agent_budget_settings` 和 `agent_budget_policies` 保存绑定作用域的策略与固定 IANA 时区。`agent_budget_ledgers` 按绑定、主备池、周期和窗口键分别累计已结算、在途和待核查用量。`agent_budget_route_states` 记录最新可信轮次的待选路或已选定状态。每个 `attempt_key` 在 `agent_budget_reservations` 保存预留、发送状态、原窗口与用量证据。人工核查的原请求、操作者与回执保存在 `agent_budget_reviews`，80% 预警按池和窗口去重并持久化。

发送标记、现有派发证据、Key 版本复核和熔断准入使用同一写事务。重启释放发送前遗留的预留，冻结已标记发送而缺少最终证据的用量。日/月换窗、撤销绑定或归档会话都保留待核查记录；后续结算与释放更新原窗口。

`gateway_loop_guards` 以绑定与会话为主键，保存可信轮次序号、去重集合、检测状态及放行序号。每次实际取得发送准入时记录该尝试的轮次和放行序号。`gateway_loop_usage` 按此归属累计已确认、在途和冻结用量，即使绑定没有预算策略也保留计量。`gateway_loop_overrides` 保存放行幂等回执。旧轮和旧放行序号的迟到结算只更新原有历史用量。

## 系统插件状态与升级

`builtin_plugin_composition` 是单例期望状态，保存格式版本、单调修订、内部服务入口以及停用/移除标识。`builtin_plugin_operations` 以操作 UUID 唯一记录原请求及回执，绑定主库持久身份；同一操作编号更换参数会被拒绝。实际运行代在内存中发布，不能把已保存的期望状态当作运行成功。

状态、相关本机来源授权撤销和回执在同一 `BEGIN IMMEDIATE` 事务提交。准备、健康检查或持久化失败保留上一运行代；提交后中断通过原回执和重启时的期望状态恢复。资源回收失败则关闭业务准入并保留恢复状态。

版本 15 升级前以 `VACUUM INTO` 创建 `local-agent.pre-plugin-lifecycle-v15.sqlite3`，核对完整性、原版本和私有文件权限。插件表、初始单例与当前版本一起提交，已有插件状态、凭据、Provider、授权和回执保留原有记录。

新库持久保存修订 0 的初始单例。未发生变更时，桌面/后台入口决定默认服务配置；首次变更后使用明确保存的配置。当前格式下缺表、单例丢失或未知记录格式均明确失败，不重建空状态，不自动全部启用。历史格式仅在明确迁移路径内允许初始化。

项目的显式启用选择随组合和回执在同一事务内保存。可选插件选择单独写入 `opted_in` 列。旧记录缺少此选择时，项目保持关闭。

账号管理首次开启前以 `VACUUM INTO` 保存私有的 `local-agent.pre-iam-v18.sqlite3`。同一事务保存首位 Owner、成员关系、恢复码哈希、登录保护标记、插件组合和版本 19 屏障。开启后的账号密码与恢复码使用独立盐的 Argon2id 哈希，短期登录会话保存在内存。模型服务创建者随服务 ID 保留，删除服务时同事务移除有效授权。恢复码绑定首位 Owner，该账号须保持为有效 Owner。

## 上传插件仓库

升级前以 `VACUUM INTO` 生成 `local-agent.pre-single-control-v16.sqlite3` 或 `local-agent.pre-single-control-v17.sqlite3`。核对完整性、源版本和私有文件权限后，在同一事务初始化六个宿主表空间并将版本从 16 升至 18，或从 17 升至 19。已有凭据恢复身份、本机令牌记录、插件组合和 IAM 状态继续使用原记录。建表失败时回滚，可修复原因后重试。

旧外围库和受管文件保留备查。插件中心在发现旧库时显示封存提示。新表空间从空的扩展状态开始，外部插件及授权需要在当前库重新建立。

服务的主库写入共用一个 SQLite 连接。插件宿主、凭据恢复和其他控制面功能通过同一个锁使用该连接。网关准入查询、模型服务状态和留存预览借用四个只读 WAL 连接。

安装包使用摘要、版本和发布者身份校验。数据库提交与包文件、选中标记的发布由现有安装日志和启动核查协调；回执/标记不能证明授权仍有效。来源与连接读取仍检查当前摘要、授权修订、运行代和资源身份。

## 容量、回执与恢复

系统插件最近 256 笔回执有界保留。界面另行保留结果未知的原请求；查不到回执仅表示当前保留范围内没有记录，不能宣称从未执行。过期请求的旧修订不能重新生效，界面不自动重放写入。其他领域继续使用各自的容量、取消围栏和恢复规则，不能为了腾出空间删除待核查证据。

动态切换的历史归档最多占用 64 MiB 的 SQLite 数据页与索引页。达到上限时停止归档及需要腾出在线空间的新预览，原操作仍可按编号查询或重试。设置页可预览并确认归档最多 128 个会话的路由租约。后台复核本批候选，并在有动态请求在途时保留租约。原始会话、请求历史及待核查记录继续保留。

`gateway_session_watermarks` 保存每个会话的可信轮次、回收水位与归档前缀，租约和派发尝试序号持续递增。路由版本满载时先按可达性清理历史 `model_service_targets` 映射，再回收无引用版本。切换记录满载时按时间归档可回收终态，待确认、待核查、用于恢复及有效绑定最近一次已应用的记录继续保留。派发尝试满载时仅回收已被可信新轮取代、结果已确认且无恢复依赖的失败尝试，仍保留旧轮关闭结论。没有合格候选时明确拒绝新增，回收与新增在同一事务内提交。

缓存回收只处理归属该能力的派生视图、临时结果与受管副本。历史请求、任务、用户配置、原始来源、凭据恢复材料和审计数据均按各自保留规则处理。插件代码版本、数据库格式版本、授权修订及运行代分别校验。

运行中的 WAL 数据库通过 SQLite 一致快照备份，不能只复制主文件。跨库恢复需要在服务停止、无写入时收集同一批数据库及相应恢复文件，核对完整性和主库身份；不能混用不同备份批次的授权、标记和业务版本。当前没有面向用户的整套多库备份/恢复产品流程，不能将单库迁移备份描述为完整备份。

工作台从无版本格式升级时，先生成只允许当前用户访问的 `tasks.pre-v1.<编号>.sqlite3` 一致性备份。备份包含已提交 WAL 数据，升级不改写旧任务和共享会话行。仓库身份、回执表与格式标记在同一事务写入。更新版本或结构不完整时停止打开工作台。恢复旧格式备份时，先正常退出使用该仓库的应用，再在独立目录验证备份。恢复点之后的记录保存在原仓库，可单独核查。

任务创建和本地发送把任务版本与接收回执同时提交。工作台保存 Agent 产品、数据来源、连接身份和实现版本，沿用原任务及原生会话编号。桌面写入复核仓库身份与插件授权代次，发送同时复核任务版本。共享服务在提交前保存待核查记录，以原生会话和消息证据确认丢失的响应。旧共享接口缺少可核实的消息编号时，结果保持待核查。

上传插件通用私有存储的配额、迁移协议与按插件清理接口须随相应 SDK 能力实现。当前上传接口开放已实现的宿主数据操作。
