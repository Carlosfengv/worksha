# 固定入口与动态路由

0.1.4 新增的单模型动态绑定支持 Claude Code CLI 与 OpenCode。Codex CLI / 桌面共用配置，可选择固定 Provider 或模型服务。Antigravity 桌面端在客户端内选择模型。

0.1.5 主入口升级为 [模型服务](model-services.md)：先将跨 Provider 模型组织为服务，再由 Agent 选择服务及默认 / 指定模型。下述 Provider 动态预览描述 0.1.4 兼容接口；原绑定、旧路由与备份继续有效，迁移需一次原生配置预览，升级不会自动改文件。

## 使用

1. 在 Agent 详情的「连接与观测」点击「接入固定入口」，选择已保存 Provider 和一个已启用模型。
2. 验证后生成原生配置事务与 AES-GCM 加密备份。首次接入仍需按既有流程退出 / 重新加载对应客户端，配置中只有固定回环地址、动态模型标识和本机认证。
3. 接入后，列表 / 详情选择 Provider 和模型会生成动态路由预览。确认发布只更新网关目标，不改 Agent 文件，不要求退出进程。
4. Agent 选择 `local-agent-default` / “Local Agent · 动态模型”时跟随该目标。已选择其他固定模型条目的会话保持原行为。

默认目标和最近实际调用分别展示。“路由已保存”不等于全部运行会话已经切换。

## 生效边界

每个明确 Session 的用户消息链使用本机密钥计算摘要，不持久保存消息正文。新用户输入必须是旧消息链的明确延伸，才允许使用新目标；相同轮次的工具结果、重试和旧请求重放使用持久化的原路由。

无法确认 Session、压缩后消息链不连续、混合或未知轮次时，保守保留旧目标。不能通过活动请求暂时为零或等待若干秒推断工具循环已结束。未保存过原路由的工具续调明确拒绝。

历史包含思考签名、加密 reasoning 等不可移植内容时，旧会话留在原路由，新目标用于新会话；不删掉内容后假装等价续聊。动态入口暂不接受 `previous_response_id` 等服务端会话引用。

首批动态槽位为文本与标准工具模式，关闭思考，不发布图片 / 文件或托管工具能力。OpenCode 目录与 Claude 首次接入配置使用保守 32K 上下文、8192 输出上限。0.1.6 修复原字节上界造成的提前拒绝，改用模型分词或明确标记的文本估算，加协议余量和输出预留；真实超限返回客户端可识别的上下文错误。旧目录声明仍为 32K，目录与能力同步规则见模型服务说明。需要其他能力时继续使用已验证的固定模型连接。

客户端版本和上游协议会影响会话兼容性。已有 Messages 连接返回的带签名空思考块仍受来源边界保护，切换时可能需要新会话。

## 存储与兼容

`local-agent.sqlite3` schema 3 增加绑定、不可变版本、操作与轮次租约四张表。版本提交与目标指针、操作日志同事务提交；请求发送前提交租约。重启读取已提交状态，不把旧工具结果重新分配给最新目标。

当前上限为 64 个绑定、4096 个路由版本、4096 个切换操作及 4096 个轮次租约；到达上限时明确拒绝新增，不自动驱逐旧续调 / 恢复引用。本版尚无自动租约归档界面。

schema 2 升级前通过 SQLite `VACUUM INTO` 保存一致性备份 `local-agent.pre-dynamic-v2.sqlite3`，权限 0600。旧 `gateway/route-*.json`、固定端口、旧 pending、加密配置备份保持原义；升级不自动改写任何 Agent 配置。

应用 / 服务版本升为 0.1.4，桌面不接管版本不匹配的旧服务。降级不能只替换旧二进制或降低 user_version；先保留新增数据，再按升级备份和原生配置备份恢复受支持状态。

## 恢复

- 「预览恢复上次路由」创建新的版本，确认后在适用的新轮次生效，进行中的旧轮次仍保留原路由。
- 「预览恢复原配置」使用首次接入事务的加密备份，沿用退出保护与逐字节恢复。外部修改会触发冲突，不覆盖用户新内容。
- Provider / 凭据版本变化或验证过期时，重新验证目标后再提交。保存 Provider 不自动更新已经发布的动态目标。
- 上游密钥仍在 Keychain；动态切换不轮换客户端本机令牌。撤权或服务停止不会自动改走其他 Provider。

默认侧车仍依赖 Local Agent 服务运行。固定地址不等于自动启用常驻服务；独立常驻 / 局域网授权沿用原边界，LAN 客户端不自动跟随本机绑定。

## 接口与验证

新增受控 IPC：`prepare_dynamic_connection(draft)`、`prepare_dynamic_route(input)`、`dynamic_route_action(changeId, action)`；分别对应管理接口 `/api/dynamic-connections`、`/api/dynamic-routes`、`/api/dynamic-routes/{id}`。旧原生配置命令语义不变。

`get_provider_status` 可选增加 dynamicBindings / dynamicChanges / dynamicLeases。请求观测可选增加 routing，记录精确 bindingId / routeVersionId、Provider revision 与边界来源；requested / routed / reported 模型继续分开。历史费用不按当前别名回算，原生记录没有精确响应关联时保留未知。

`pnpm test:dynamic-routing` 使用临时目录和本机模拟上游验证并发切换、工具续调、旧请求重放、多 Session、配置摘要、鉴权、加密备份与逐字节恢复。
