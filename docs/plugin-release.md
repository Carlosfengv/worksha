# 插件升级与回退

插件 SDK 的声明、协议和示例见 [SDK 指南](../sdk/plugins/README.md)。升级与回退必须按实际存储版本和兼容性处理。

## 升级

1. 正常退出旧窗口；开启常驻网关时，用旧服务对同一数据目录执行 `gateway stop`、`gateway uninstall`，再使用新服务安装。
2. 在服务关闭后备份完整数据目录、相关配置和原 Keychain。运行中的 SQLite 需使用 backup API 获取一致快照；逐文件复制 WAL 不构成一致备份。数据库副本不包含系统钥匙串的迁移能力。
3. 用新 App 启动同一数据目录，核对 Provider、会话、来源授权及插件状态。桌面拒绝接入不兼容服务，不强行停止用户实例。
4. 用新服务在原目录 `gateway install`。保留原监听、客户端授权及密钥；目录被占用或旧定义未卸载时停止并核查。

插件安装、启用与来源授权是独立步骤；新版本需重新核对签名、能力和权限。插件缺失、损坏、未来版本或依赖不可用时保留明确错误，不生成空库覆盖原文件。MCP 连接不因重开自动启动。

## 恢复与回退

配置操作结果未知时查询原操作 ID，不建立重复写入；原文件被其他程序修改时遵循冲突提示。插件卸载后，宿主仍可按原身份核查配置备份，恢复需要原密钥和可读账本。

回退前停止连接、核查未完成事务、正常退出并保留完整受管副本。主库已有版本屏障，旧程序可能拒绝较新 schema；不得仅凭版本号宣称可回退。需要回退时使用经过实际同数据往返验证的产物和对应一致备份，不删除数据库或重建客户端密钥绕过检查。

当前开发签名包不代表 Developer ID 分发、Apple 公证或自动更新渠道已验证。
