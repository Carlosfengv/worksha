# 架构与模块边界

Local Agent 由原生桌面窗口、独立 Rust 本地服务和可独立测试的 core 组成。Tauri 随包携带界面资源与服务，通过受控命令访问本机能力。启动与检查入口见 [README](../README.md)，开发约定见 [AGENTS](../AGENTS.md)。

## 前端

```text
src/main.tsx → app/App.tsx → features/<领域>/页面
                  ↓               ↓
             插件与路由组合    组件 / Hook / 普通规则
                                  ↓
                         领域 api.ts → desktop-command
```

`app/` 持有外壳、路由、页面错误边界、快照初始化与内置插件组合。领域模块集中页面、状态、组件、API 和类型；跨领域使用明确的 API、类型或业务组件，不能导入其他页面或产生运行时循环。`shared/` 提供无业务反向依赖的公共能力。

Zeron 安装文件由 `.zeron/install-state.json` 校验，不属于可直接修改的业务层。组件选择、语义样式与滚动归属见 [Zeron 使用约定](zeron-usage.md)。

轮询与共享读取按完整参数和生命周期合并在途请求。`reload()` 合并普通读取；变更后的 `invalidate()` 使旧结果失效并安排新读。切换来源、筛选、停用或卸载后，旧回复不能覆盖新状态；忽略旧回复不代表后台工作已取消。

写入结果未知时，保留原来源、版本、请求与操作编号，显式查询持久回执；恢复界面不自动重放变更。页面错误边界保留导航，重试不重新执行业务写入。

后台可用能力改变后，使当前界面的读取失效并重新核对；等待原操作回执的恢复路径同样刷新读取，防止功能恢复后继续保留旧错误。插件状态、来源授权、模型连接和实际业务数据各自保持状态，服务配置预设作为内部实现保留兼容性。

插件中心在一个列表中展示系统自带与用户上传的插件，按安装渠道标记来源；包内清单不能改变来源归属。统一上传检查使用原包校验器，再由宿主按能力选择执行与授权流程，保留原接口兼容。准入规则见 [插件标准](plugin-standard.md)。

插件中心按完整业务功能登记实际入口、操作和使用条件，功能场景仅用于查找。系统业务插件与只读支撑在同一依赖图中注册。系统目录的实际状态来自后台，前端据此控制导航与深链，后台准入同时覆盖旧接口、领域接口和本机网关。停用业务插件回收归属它的支撑，卸载持久保存移除状态。系统随附代码作为可信重装来源，历史数据与配置保留。启用只联动必需依赖。回执、撤权、取消与明确恢复入口保持宿主所有。变更绑定数据库、修订、运行代和已核对的影响。未知结果保留原编号供核查。

## Rust

| 位置                                          | 职责                                                   |
| --------------------------------------------- | ------------------------------------------------------ |
| `src-tauri/src/lib.rs`、`menu.rs`             | 命令注册、原生插件、窗口与退出流程                     |
| 桌面 `commands/`                              | IPC 校验、文件选择与保存等原生适配                     |
| 桌面 `backend.rs`、`backend/`                 | sidecar 生命周期、认证 HTTP、连接身份、超时与诊断      |
| service `main.rs`、`routes.rs`、`api.rs`      | 进程入口、HTTP 路由和管理鉴权                          |
| service `state.rs`、`tasks.rs`、`blocking.rs` | 状态所有权、采集调度与有界阻塞任务                     |
| service 领域模块                              | 调用 core、插件宿主与网关协作、结果转换                |
| core 领域模块                                 | 数据模型、SQLite、原生来源解析、配置事务与普通业务规则 |

core 不依赖 Tauri。文件扫描和数据库等阻塞工作通过有界 worker 执行，取消等待者不提前释放仍在工作的准入名额。历史查询、管理写入、账户刷新与流式网关分别受容量约束；资源隔离不代表数据库锁隔离。

桌面连接固定后台身份与连接轮次。复合命令在原生对话框、分批导出、配置检查与应用之间持有同一 `ConnectionContext`，连接变化后不自动切到另一个后台继续写入。诊断只保留有界固定类别，不记录凭据或正文。

## 数据与安全

管理接口验证令牌、Host 和 Origin，后台凭据不返回界面。主配置库保留持久身份与版本屏障；迁移、操作回执、取消围栏及配置备份按领域事务处理。SQLite、原生文件和系统钥匙串不是联合事务，不把 HTTP 失败直接解释为未执行。

账号管理开启后，宿主在进程通信认证之外校验应用账号会话。桌面在挂载业务工作区前读取登录状态，登录凭据由 Rust 连接持有。原有管理 API 和桌面业务命令归 Owner，Member 经专用接口读取绑定的模型服务摘要。探活、进程退出、模型网关与采集使用各自的机器凭据。当前账号管理仅适用于应用和受控 API 的访问边界，资源授权以默认租户内的账号为单位。

桌面在验证后台运行身份时协商 IAM 协议。未声明该协议且缺少 IAM 接口的旧后台可继续本地使用，需升级后才能开启账号管理。声明支持但缺少接口时关闭业务准入。桌面连接以会话轮次隔离在途响应，成员资源响应沿用宿主对模型服务的在途准入。

各库的数据归属、插件状态事务、版本升级与卸载保留规则见 [数据库设计](database-design.md)。主库版本 16 阻止旧版忽略系统插件停用状态；上传插件的固定仓库采用原子初始化，损坏或未知格式不重建为空库。

原生会话与活动按明确授权读取；发现目录、安装插件、启用能力、验证连接和成功读取是独立状态。请求、会话与项目的关联使用可证明身份，无法关联时保留未知，不按显示名猜测归属。

统一领域读取通过版本化契约和独立插件存储组织，来源、授权、游标和冻结快照分别校验。旧 IPC 与新增契约并存，由 `check:architecture` 和生成绑定检查保护。对外协议与生成类型保存在 `contracts/`。

内容留存目前提供偏好、只读预览和统计事实基础，完整发布、到期删除及恢复尚未形成产品闭环。原始数据、配置、凭据和操作回执分别按其所有权与生命周期管理，不能直接删除原始行冒充完成归档。

## Agent 任务工作台

任务工作台待接入，当前未挂载。项目页面已作为默认关闭的内置插件单独注册。下文说明保留的任务实现与存储约定。

前端 `features/workbench/page.tsx` 组合看板、任务创建和会话页面；`task-setup.tsx` 管理项目与模型选择，`task-conversation.tsx` 管理发送、审批、停止和交接，`session-thread.tsx` 将消息交给 Zeron ChatThread 展示。增量读取按任务编号与消息版本合并，迟到结果不能覆盖较新的会话状态。原生目录确认和任务创建使用同一份后台连接上下文，连接变化后拒绝继续创建。查看单个任务时只刷新该任务的原生历史，看板读取再刷新全部任务。

共享 OpenCode 的模型入口按实际 Provider 设置核对网关归属。当前实例、本机其他实例、外部直连和未知分别展示；指向其他实例或归属未知的入口在发送前拒绝，不自动换模型。界面只接收归属类别，不接收 Provider 凭据。任务的模型请求按原生会话 ID 精确筛选；请求详情仅在当前看板包含同一原生 ID 时接回 ChatThread，否则保留该 ID 的既有会话请求入口。

任务在原生目录选择后绑定项目、Agent 与模型路由。新建 OpenCode 任务通过官方默认本机服务创建，SQLite 保存任务请求编号、原生会话、服务来源、目录身份和初始消息。原生会话与首条消息使用稳定编号处理重试，重开时核对原生身份后恢复卡片，结果无法确认时保留未知状态。模型目录来自原服务，响应只返回界面所需的模型标识和名称。旧任务使用原 App 会话目录。

新建 Claude Code 任务使用所选来源的 `.claude` 原生记录目录，旧任务按原私有目录恢复。CLI 通过受控模式和双向 JSON 消息执行，支持用户配置中的 API 凭据与受验证的 Local Agent 网关凭据引用。原生 CLI 继续后，工作台复用 core 会话解析器导入后续消息，保存读取位置与历史指纹以防重复和历史改写。发现同一原生会话仍由存活的客户端占用时，工作台显示占用并阻止再次发送。路由失败保留原选择。命令与文件修改请求单次审批。批准的 Shell 命令按本机用户权限执行。

CLI 与共享 OpenCode 使用相同的当前网关监听地址规则，CLI 创建任务和发送前拒绝其他实例或未知归属。请求返回任务使用只读的原生 UUID 精确查询，重复绑定保留未知，不按标题猜测。CLI / Desktop 配置状态在工作台读取响应中独立刷新，不依赖任务消息版本；仅向界面返回归属类别、配置错误及不含凭据的 CLI 续聊命令。Desktop 配置沿用 core 的官方第三方推理 Profile 适配器与组织策略保护，接续说明区分同一原生 CLI 会话与 Desktop 新会话上下文交接。

跨 Agent 交接创建一个链接到原任务的新会话。OpenCode 共享会话可以打开官方 Desktop，并复制标题供搜索定位。Claude API / 网关任务在界面说明官方原会话 Desktop 接续的订阅登录条件，支持预览并复制交接内容。旧 OpenCode App 会话可导出脱敏 JSON 副本。

接管 OpenCode Desktop 会话时，两个客户端连接到同一个已认证的本机服务。工作台按用户操作读取官方本机服务连接记录，核对文件权限、服务地址和监听进程，再验证活动会话接口。手动连接支持旧版共享服务接口。版本号仅供展示。工作台按原会话 ID 读取流式回复和待审批项，向原服务发送续聊、单次审批和停止请求。工作台在内存中持有连接和凭据，断开工作台连接后原服务继续运行。Claude Desktop 的运行中会话通过官方客户端控制，工作台提供内容交接。

## 扩展与部署

内置 Rust / React 插件参与可信应用组合；外部包使用签名校验、Wasm worker、独立来源授权、版本准入与有限配置操作。MCP stdio 程序按当前用户权限运行，其边界与 Wasm 不同。接口见 [SDK](../sdk/plugins/README.md)，维护操作见 [插件升级](plugin-release.md)。

`core/plugin` 维护系统自带能力的地址、版本、实例、依赖、操作种类及资源范围。service `plugin_host` 在同一宿主注册系统业务功能，以及会话来源、账户来源与采集支撑。项目模块声明自己的路由、页面和支撑组件，首次启用须明确选择。任务的旧注册 ID 仍用于兼容已保存的配置与回执。停用业务功能会停止它拥有的支撑，领域目录按当前租约发布实际状态。系统功能的启用状态与来源授权分别核查，用户上传包通过独立的签名与权限准入。

同一运行模式内切换插件时，暂停涉及的能力并等待相关响应结束，其他插件保留现有运行实例。运行模式改变或恢复组合时暂停全部业务，归属未分类的请求也按全局请求处理。宿主校验完整依赖图，将配置、来源授权撤销和回执写入同一 SQLite 事务，再回收受影响的旧作用域。准备和保存失败保留原状态，提交后失败关闭业务并保留诊断。缓存发布核对原激活租约，采集任务随所属插件回收。

桌面、后台与恢复使用同一服务二进制。部署预设由宿主管理，插件中心按业务功能展示安装、运行与依赖状态。恢复模式保留快照、插件目录、操作回执、来源撤销和恢复入口。工作台的任务执行由原适配器负责，功能切换前核查在途任务。系统插件管理契约由 `contracts/plugins/builtin` 的 Rust schema 生成，写入结果未知时沿用原编号核查。

上传的 Agent 来源按声明能力向 Agents、Sessions、请求、活动和项目发布数据。停用来源会从业务目录移除贡献，插件中心继续管理包与授权。声明 `agent.connection@1` 的 Agent 共用模型切换入口，写入通过各自桥接完成。来源读取与模型连接分别授权，已使用的网关入口在恢复时撤销，保留请求历史。

随附 DSH 模型连接通过用户目录中的私有连接桥接提供，首次切换时单独授权。会话来源在插件中心启用并选择文件。已有文件授权的 DSH 来源仍可使用所选目录中的连接桥接。

普通桌面服务随应用退出；独立常驻服务通过显式 LaunchAgent 管理，桌面退出不停止它。LAN 模型入口使用独立客户端授权和监听配置，详见 [常驻网关](standalone-gateway.md)。模型版本、绑定和发布分别持久化，见 [动态路由](dynamic-routing.md)、[模型服务](model-services.md) 与 [策略恢复](../sdk/plugins/docs/routing-policy-recovery.md)。
