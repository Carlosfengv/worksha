# 模型服务

0.1.5 在固定入口上增加模型服务（模型组），0.1.6 增加优先级、失败回退和限流切换。Provider 保存模型来源、协议和凭据；模型服务维护对外模型目录、默认目标和能力声明。Claude Code CLI、Claude 桌面端、OpenCode 及 Codex CLI / 桌面端可在同一个「切换」菜单选择 Provider 或模型服务。直接选 Provider 时可跳过创建和发布服务。

## 使用

1. 在 Providers 配置来源、启用需要的模型。
2. 打开「模型服务」，创建服务，可添加不同 Provider 的模型。为每条目填写显示名称、上下文窗口、最大输出和工具支持，选择默认模型并「验证并发布」。短请求只验证连接与协议；能力数值由维护者按上游文档声明，不代表完成满窗口、所有工具或多模态验证。
3. 在 Agent 列表或连接详情选择模型服务。验证后生成预览和 AES-256-GCM 加密备份，退出客户端后写入配置，再启动客户端。
4. 在客户端选择「默认」或具体模型。默认使用 `local-agent-default`；具体模型使用稳定的 `local-agent-model-<条目 UUID>`。Claude 桌面配置与网关目录使用对应的稳定桌面 ID，内部目标和 Provider 可调整。
5. 修改并发布默认目标或条目的上游来源，已接入客户端无需重启。网关在可确认的新用户轮次采用新版本；同轮工具调用、重试和重放保留原版本。指定模型继续选择同一条目。

服务最多 64 个，每服务最多 32 个模型。更新有版本冲突保护；已被 Agent 配置引用的服务不能删除。OpenCode 的非默认 Provider 模型目录仍可由用户选择，也计入引用；切换默认服务不等于移除旧目录。删除为保留历史引用的逻辑删除。

## 发布、删除与结果核查

当前前端先确认后台提供版本 1 的写入核查协议，再开始验证和提交；不支持协议的旧后台停用发布 / 删除，不降级为无编号写入。编辑器和删除确认保留打开时的数据库身份，首次提交前切换到另一个库会保留草稿并拒绝继续。来源身份未知的旧草稿需要关闭弹层、重新打开并核对。短期连接恢复不等于数据库身份变化；同库重启可继续核查原操作。

每次发布 / 删除生成稳定 operationId。变更和回执在 SQLite 同一事务中提交，相同编号与相同参数返回原回执，不重新验证或新增版本；同编号换参数拒绝。发布回执引用不可变版本，后续修改或逻辑删除不改写原结果。回执库损坏时返回不可读状态，保留原记录。schema 8 库的身份行 / 表丢失或身份非法时拒绝初始化，不分配新身份、不清空旧回执；只有新库及升级阶段可以创建身份。

传输断开、超时或无法核对响应时，界面先查询原编号；尚未确认则保留草稿和编号、暂停新的验证与提交，提供显式查询和同编号重试。重试仍核对原数据库，不触发新的模型验证。页面重新打开会列出待核查操作，不自动重放变更。确认提交后，界面刷新失败不改变已提交结论。

浏览器本地恢复记录只保存在用户发起验证后、准备提交的冻结业务参数，采用字段白名单，包含服务 / 模型名称、ID、能力与路由参数，不含 Provider 对象、Endpoint、凭据或会话正文；最多 16 条，每条最多 64 KiB。写入恢复记录失败或存在不可读记录时停止发起新变更。记录不是未保存草稿的自动备份。

服务端最多保留最近 256 个操作回执；回执缺失可能是未执行、记录淘汰或连接到了错误来源，不能当作确定未执行。核查不补发模型验证；验证缓存到期、旧 revision 或容量限制仍可能阻止未提交操作的重试。回执淘汰后的长期人工核对与恢复记录整理仍需完善，不承诺无限期自动恢复。

旧 `save_model_service` / `delete_model_service` IPC 和 HTTP 形状保留兼容；当前发布 / 删除界面使用提交、查询与带数据库身份的成员验证接口。该能力在 schema 8 引入，从 schema 7 升级前保存 `local-agent.pre-model-service-operations-v7.sqlite3` 一致性备份；当前主库已继续演进，实际版本以存储迁移代码为准。

## 能力与目录同步

模型服务发布文本与标准工具。客户端思考控制关闭。上下文 2048–2000000 Token，输出 16–65536 Token 且小于上下文。默认入口发布全组共同支持的最小窗口、最小输出与工具交集，因此默认可跨成员切换而不扩大承诺。

常规 Messages 来源使用 `thinking.type=disabled`，已识别的 Ollama OpenAI 兼容来源使用 `reasoning_effort=none`。MiniMax Flash 的内置推理按订阅适配规则处理。已有历史块保持原样，已产生签名思考历史的会话仍受原路由保护。 [Ollama 官方兼容文档](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx)

OpenCode 每个目录条目注入独立的上下文、输出和工具 / 模态信息。Claude Code 使用原生 `modelPicker` 提供默认与具体条目，并显示各模型声明；其未知模型上下文和输出环境配置是全局设置，统一使用组内保守上限，不承诺按菜单项动态改变 Claude 内部压缩窗口。

Agents 和插件中心分别提供 OpenCode CLI 与 OpenCode Desktop。两者共用 OpenCode 的用户级模型配置和会话来源授权。从任一入口切换 Provider 或模型服务都会更新共享的默认配置，项目配置仍可能覆盖默认设置。模型服务规则可匹配全部 OpenCode 请求，也可单独匹配 CLI 或 Desktop。客户端归属依据请求中明确报告的身份。停用任一产品插件后，该端的请求按 OpenCode 客户端来源未知进入通用路由，另一端继续匹配自己的规则。旧版无客户端标识的流量和旧记录也归为来源未知。OpenCode 2.x 的共享后台服务报告的是服务进程的身份，同一服务处理来自两个界面的请求时，Worksha 按它报告的身份记录。

项目规则可使用已授权扫描确认的 OpenCode 1.x 或 2.x 会话目录。规则编辑器可搜索和选择只在 2.x 会话库中出现的项目。撤销来源授权或隐藏项目后，选择列表移除对应项目，新轮次按其他适用规则选路。

授权后，会话列表和详情可读取 OpenCode 2.x 保存的标题、正文、工具文本及响应 Token。未生成标题时使用首条有效用户文本。同一会话在两个库格式中都有记录时，优先读取 2.x 历史。派生会话可查看继承的文本，Token 和调用统计只计入自身记录。用户附件仅展示数量，回放数据与文件内容留在 OpenCode。

活动视图读取 OpenCode 2.x 最近的用户消息、工具状态和原生结束标记，支持内联片段与分表片段。活动只展示工具名称和状态，命令、参数和结果可按授权在会话详情查看。最新轮次以外的运行中工具视为历史，结束标记区分完成、失败和中断。客户端归属仍以可核对的证据为准。

Claude 桌面端复用已应用的本机第三方推理 Profile。Codex CLI 与桌面端共享用户配置和目录，应用前需退出两端。Codex 模型服务接收完整 Responses 输入，可处理文本和标准函数工具。服务端会话引用、思考模式与托管工具仍走各自的兼容连接能力。

OpenCode 默认聊天也可能附带工具定义，即使目录的 `tool_call` 为 false。对未发布工具能力的文本入口，工具选择省略或为 `auto` / `none`、且没有工具历史时，网关在上游请求中省略可选工具定义及选择参数，按文本完成聊天；能力声明保持关闭。强制调用、未知工具选择、托管工具和已有工具历史仍明确拒绝，不擦除历史；带工具历史的会话应选择支持工具的模型或新建聊天会话。上游意外返回的工具调用也会在发给客户端之前拦截，包含流式及同协议响应；已发布工具能力的服务保持原有调用行为。

OpenCode 的系统提示由所选智能体决定。日常聊天可配置独立的 Chat 主智能体，设置聊天提示、服务模型 ID 和工具权限。`default_agent` 指定新会话的默认智能体。配置方式见 [OpenCode 智能体文档](https://docs.opencode.ai/docs/agents/)。

Claude 2.1.310 的实际目录接口会对未知逻辑 ID 返回通用的 effort / adaptive-thinking 标志，`modelPicker` 无独立的布尔能力覆盖字段。本版通过说明文本告知服务能力、默认关闭思考，并由网关拒绝未发布的思考 / 模态；不能保证隐藏 Claude 自身的通用能力选项。OpenCode 的实际目录接口已读回文本、工具、思考关闭与窗口限制。

新增 / 删除条目、改显示名称、变更能力会提示「目录待同步」。客户端通常在启动时读取原生配置，本版不会强制刷新进程内菜单；使用「同步模型目录」生成新的配置预览，退出并重新启动客户端。原已安装目录仍是网关的能力契约；新目标能力低于该契约、指定条目被移除或请求模型未发布时明确拒绝，不静默降级、截断历史或扩大能力。

## 路由策略

在服务编辑器启用「路由策略」后，默认入口按优先级选择；指定入口始终先尝试用户选中的逻辑模型，然后按组内顺序回退。回退只改变本轮实际目标，不改客户端选择；冷却结束后的新轮次仍优先尝试指定模型。优先级首位也是默认模型。可单独暂停候选，至少保留一个启用项。

可分别开启临时失败回退与限流回退，并设置最多尝试 1–5 次、整轮等待 5–300 秒、冷却 1–3600 秒。连接明确失败、HTTP 500 / 502 / 503 / 504 / 529 和输出前收到的明确临时协议错误可触发失败策略。429 与配置的并发 / 每分钟限制触发限流策略。401 / 403、参数错误、上下文溢出、余额不足等默认结束本轮。重试次数按实际发送计，候选被冷却或本机限额跳过不计发送次数。

限额按来源账户与上游模型共享计数，配置入口支持并发数和每分钟请求数，0 表示不设此项限制。使用同一凭据和模型的固定服务也贡献实际发送计数。有配置限额的服务按共享计数应用自己的上限。发送前先保留名额，发起上游请求时才计入每分钟请求数。发送前被拦截或取消会释放该名额。429 冷却按同来源账户共享，临时失败按模型冷却。优先使用上游给出的单一有效 `Retry-After`，限制在 1–3600 秒。缺失、重复或无法解析时使用已发布的冷却设置。冷却持久化，到期后由该账号的一条请求探测恢复。模型服务列表、发布前预览和上游账号详情可区分冷却中、待恢复探测和账号恢复探测中。恢复记录与额度探测和连接验证分别显示。分钟计数与并发在本机进程内维护，服务重启后重置。

固定模型服务与智能路由共享上游冷却，发送前会再次检查。如果此时发现冷却，固定入口返回等待提示，智能路由可按发布策略选择备用。被拦截的请求不会延长原冷却。冷却到期后，固定入口和智能路由共用一次恢复探测。

限流或临时故障后的流式探测收到协议结束事件才确认恢复。探测仍在输出时，新轮次可按策略走备用，固定路由的续调等待原目标。探测明确失败时重新冷却。探测到达发送关口后，如果超时、取消、响应中断或后台重启导致结果无法确认，已记录的范围按当时的路由策略重新冷却一次，原有的更新冷却记录继续生效。冷却到期后，首个可用请求可以再次探测。

候选须满足已安装入口的完整能力契约，不自动缩小窗口。只有可信 Session 的明确新用户轮次且历史可移植时才开启候选计划；同轮工具结果、已有签名历史或未知边界保留原目标。模型开始输出正文 / 工具调用后不拼接其他模型；后续中断只影响未来轮次的冷却。发送超时或重启后结果未确认时保持 pending，不自动重复可能已计费的请求。

Messages 请求的输出量超过入口声明时，网关拒绝发送，并为修正后的同一请求保留原发布策略。只有通过输出校验的记录才能作为后续轮次的选路依据。OpenCode 自动生成标题等辅助请求被拒绝后，原会话的用户轮次仍可继续选路。

OpenCode 可能在空回复后把相邻的用户输入合并到一条模型请求消息。启用 OpenCode 会话来源后，Worksha 可按原会话核对这些输入的边界。只有已保存的历史与新轮次都能核对时，才重新选路。来源未授权或历史无法核对时，继续沿用原目标。

旧版受超限标题请求影响的 OpenCode 2.x 会话也可通过已授权的原生用户消息核对恢复选路。Worksha 需要匹配原会话的文本历史及已保存的用户轮次。能够辨认且没有发送状态的旧标题记录可以跳过，精确重试与历史记录仍保留。

旧服务升级后策略默认关闭，行为继续跟随默认 / 指定目标；启用或调整策略只需发布服务，不改客户端文件。

### 子服务路由

在服务编辑器选择「添加子服务」，然后选择一个已发布版本。父服务把该条目作为一个候选。走到该条目时，子服务按自己的条件、排序、账号池和回退设置选择实际模型。只有子服务走完可用候选，父服务才根据自身回退设置决定是否继续。父服务的尝试次数和总等待时间覆盖整轮，子服务也受自己的上限约束。同一轮候选中，父子服务重复引用同一上游账号和模型时，只尝试一次。

子服务条目继承所选版本的共同能力，可以在父服务中设置整组并发和每分钟请求上限。账号池和意图分类模型在实际来源所在的服务中设置。父服务最多展开三层和 128 个模型或账号候选，发布时拒绝循环引用。

接入父服务时复核子服务的已发布来源配置和账号状态。子服务的连接短请求在发布该版本时完成验证。

子服务发布新版后，在父服务中选择新版本并重新发布即可升级。原轮次的工具续调和重放保留实际来源、账号和子服务版本。请求详情显示经过的子服务及实际模型。仍被已发布服务引用的子服务需先解除引用，才能删除。

子服务只有在被实际尝试时才运行意图分类。父服务和所有子服务共享整轮的一次分类机会。分类发送仍要求该版本是子服务的当前发布版本，旧版父引用按其他条件继续路由。使用外部排序策略时，子服务版本也须通过其自身的策略授权核查。

### 条件路由

在模型服务编辑器启用路由策略，再按优先顺序添加最多 16 条规则。每条规则选一个服务内模型，可组合客户端、项目、是否附带标准工具定义、是否流式，以及最低输入 Token 数。输入量使用网关的计数或估算结果。一个规则里的条件须同时满足。

规则只在默认入口可确认的新用户轮次求值，客户端条件支持 Claude Code、OpenCode（全部客户端、CLI 或 Desktop）和 Codex。第一条匹配且目标已启用、满足已安装能力契约的规则决定优先模型。请求未匹配时按默认顺序处理。明确选择某个模型的请求按原有的指定模型策略执行。匹配的模型使用自己的账号池、配额和冷却策略。绑定外部策略时，它仍能排除候选，保留的规则目标优先，其余候选按外部顺序尝试。

项目从已授权的本机会话索引精确关联。项目未索引、已隐藏、授权已撤销、会话与项目的关联有冲突，或请求来自局域网时，项目条件不会匹配。项目路径和请求正文均不写入规则或传给外部排序插件。

规则随服务版本发布，同一轮重试和工具续调保留已选计划。请求详情显示匹配规则、客户端选择和实际使用的模型。

### 可选意图分类

在「意图路由」启用分类，选择一个已启用的服务模型。如果该模型有账号池，再指定一个固定账号。给条件规则填写意图标签，例如「排查错误」，并按优先级排序。可组合客户端、项目及其他条件；排在前面且已经匹配的普通规则直接生效。

只有本机默认入口中可确认的新轮次可能发起分类。分类输入限于最新一条用户消息的过滤片段和适用的标签列表，最多读取 1600 字，过滤常见凭据和客户端注入。每轮最多一次分类请求，限时 2 秒，可能产生额外费用，在请求记录中单独显示。外部策略采用拒绝模式时，分类也会检查绑定授权。答复模型按配置的外部策略排序。分类结果限于配置标签，超时、无匹配或连接不可用时继续评估其他规则。请求详情保留分类结果和实际路由，同一轮重放和续调沿用原计划。

网关在发送分类请求前保存本轮的分类归属。答复计划尚未保存时取消或重启，重试会复用同一服务版本和分支中仍适用的已确认标签。分类已发送但结果未知时，直接继续评估普通规则。答复计划和分类记录均缺失的旧轮次也按普通规则处理。这条记录关联轮次、版本和分支，可保存确认的标签或无匹配结果。

分类与答复共享发送容量、额度暂停和上游冷却。账号健康时，分类可按配置并发。上游冷却到期后，分类与答复共用一次恢复探测。分类收到明确的额度拒绝、HTTP 限流或临时故障、已核实的凭据或模型权限拒绝时，网关按对应范围更新状态，再按普通规则和已发布的回退条件继续本轮。等待额度恢复探测的账号只接收符合条件的正常答复请求。

### 同模型账号池

在供应商详情的「上游账号」登记默认凭据或添加独立 API Key，再在模型服务编辑器启用路由策略，给模型条目选择账号顺序。发布前分别用每个新增或变更的账号验证该条目的模型。每条目最多 8 个账号，一个服务版本最多 64 个账号引用。未配置池的模型沿用原来的 Provider 凭据。

在编辑器的「发布前路由预览」选择默认入口、指定模型或一条命中的条件规则，可查看首选目标、跨模型回退范围和账号池顺序。预览会按固定的子服务发布版本展开，并标出账号暂停、撤销、版本变化、验证过期、冷却或已知额度状态。预览只读取本机记录。结果带核对时间，草稿变化后需要重新读取。实际选择仍取决于客户端已安装的目录、请求和运行时状态，短请求由「验证并发布」触发。

在「上游账号」打开「验证与状态」，可选择已启用的模型，用该账号单独发送一次短请求，可能产生用量。按模型查看验证结果和时间。通过记录有效期为 15 分钟，供应商配置或账号版本变化后需要重新验证。这里也能看到账号或单个模型的冷却原因和截至时间。点击「刷新状态」会重新读取本机记录。

切换到「用量与额度」可查看当前账号版本的官方额度窗口或余额。读取官方用量前需要确认。更换 Key 后，新版本的额度在确认读取前显示为未知；缺少可关联额度来源时也保持未知。

接入 Agent 时，含账号池的模型使用其已发布账号生成配置预览。只配置了账号池的 Provider 可以直接接入。

网关在可确认的新轮次先尝试首选模型的账号。按策略在明确限流或临时故障后切换账号。只有明确开启「账号池耗尽后允许跨模型回退」才尝试备用模型。工具续调沿用已选账号，账号撤销后原轮次拒绝发送。请求详情记录实际账号名称和尝试结果。

首次回退或本轮再次尝试首选失败时，普通文本回复会显示路由提示。直接模型条目在同一模型内回退时，提示会说明已切换账号，并显示继续使用的模型。账号池采用固定顺序且关闭跨轮亲和时，原会话切回同一首选账号也会显示恢复提示。提示只面向可确认的新用户轮次，每轮最多一次。

模型服务可另行开启「上游明确拒绝凭据或模型权限时回退」，默认关闭。网关依据完整 HTTP 错误响应中的状态与结构化错误码确认原因。401 配合 `invalid_api_key` 标记该端点和协议下的凭据，403 配合 `model_access_denied` 或 `model_not_found` 只标记该凭据访问的模型。若响应包含错误类型，该类型也要与拒绝原因一致。标记按服务的默认冷却时间到期，期间由供应商详情显示。启用路由策略的服务在准备好凭据与请求后再次核查拒绝状态。此时跳过的候选不计实际发送，也不会延长拒绝时间。恢复探测只覆盖预留时已经到期的限制。工具续调和严格固定账号的会话保留原目标并返回拒绝。含义不明的 401、403、额度不足和结果未知仍直接返回对应错误。

错误正文超限或读取失败时，网关保留上游 HTTP 状态和单一的 `Retry-After`。参数错误仍直接返回，429 按已发布的限流回退设置处理。

「请求详情 → 候选路由决策」按本轮记录展示排除原因、父子服务发布路径和账号池位置。如果可用账号先获选，因容量、冷却或额度等原因排在后面的账号会注明排序时的状态。其他未尝试的候选会注明已有候选获选、达到时限或路由停止等原因。发送前结束的请求也能查看决策，尝试和模型用量仍取自实际发送。查看权限沿用本机请求详情，账号显示为发布时的池内位置。

实际发送的尝试保留账号显示名、选择原因和回退原因。请求记录及历史详情隐藏内部账号 ID 和修订号，CSV 保留尝试计数。开启应用账号管理后，获授权的 Member 可查看服务摘要，上游账号管理、请求详情和导出由 Owner 访问。

上游完整错误响应里的已报告用量和受支持的实际费用计入原失败尝试。回退后的响应有独立记录。未完整读取的错误响应和缺少费用证据的尝试保留相应的未知状态。

官方 OpenRouter 可能先发出 HTTP 200，再在 JSON 或流式事件中报告失败。网关按响应里的限流、临时故障、账户余额、权限和内容策略分类处理。限流回退沿用发布开关和上游的 `Retry-After`。响应内的鉴权拒绝只结束本轮。完整失败响应里的 `usage.cost` 和 Token 归入原账号，备用响应分别记录。[OpenRouter 错误格式](https://openrouter.ai/docs/api_reference/errors-and-debugging)

官方连接在输出前返回明确的预算耗尽 403，或标明密钥限额耗尽的 402 时，网关保存对应凭据的暂停状态，按已发布的限流回退条件继续。带有效 `Retry-After` 的在途预算 402 按临时限流处理。普通权限拒绝、内容安全拒绝及单请求金额过高的 402 结束本轮。错误响应里的预算类型用来识别受限凭据，共享成员和工作区的归属以官方额度查询为准。[OpenRouter 额度与限流](https://openrouter.ai/docs/api_reference/limits)

达到总等待时限时，网关根据发送记录区分两种结果。已确认本次候选未发送时，保存超时记录，冷却结束后可按原轮次重新请求。已尝试发送且结果未知时，保留原轮次的防重记录并提示上游结果未确认。

上游返回成功状态后，如果首个可交付输出之前出现响应中断、超限或协议无法解析，且没有完整的结构化拒绝，网关也保留原尝试为待核查。服务重启后，同一轮次仍会拦截重试。收到明确的限流或临时故障时，仍按已发布的策略决定是否回退。已经开始输出后出现中断时，当前响应就此结束。

流式响应按事件先后判断是否已开始输出。同一批数据里先到达正文或工具调用、后到达错误时，客户端仍会收到先前的内容和中断提示，本轮保留原上游。

上游在协议结束事件前关闭连接时，请求详情将该次尝试标为中断，首选模型进入冷却。协议结束事件表明输出达到上限时，本轮按该结果结束。客户端主动停止读取时，只有已观察到的上游故障会影响冷却。

流式请求收到普通 JSON 成功响应，或非流式请求收到事件流时，也按上游结果待核查处理。请求详情保留原 HTTP 状态和已确认用量。完整的结构化拒绝仍按实际错误分类。

客户端压缩或改写历史后，网关从原轮次核对已确认的模型和账号。原轮次仍在执行或结果待核查时，改写后的历史和工具续调都会等待原结果。原轮次明确失败或旧历史记录与最终路由冲突时，可重试原轮次或开启新会话。请求详情会显示拦截原因。

网关在检查输入前为同一轮保留发送权。参数检查结束前到达的重复请求返回 409，请求详情记录零次发送。如果新轮次在保存路由计划前因参数无效结束，修正参数后可按原轮次重新规划，仍使用原入口的发布策略。缺少可核对选路状态的旧轮次需要开启可识别的新轮次。

路由计划已保存后，网关仍会在发送前单独保存发送记录。若客户端取消或服务退出，且该轮所有答复尝试都有未发送的证据，重试原轮次会沿用保存的候选计划。上一候选已明确失败且原策略允许回退时，网关一并保存失败结果、冷却状态、剩余候选、各层尝试次数和截止时间。若备用候选尚未发送，重试从保存的进度继续。涉及外部策略时，原排序授权也须通过重新核对。

发送记录与本次占用的额度恢复和上游冷却探测名额同时提交。任一记录写入失败时，本次候选零发送，原有的待探测资格继续有效。

凭据和协议准备结束后，发送前再次核对原策略授权。准备期间解除绑定会拦截尚未发送的候选。已有上游失败结果和回退进度继续保留，同轮重试仍须核对原授权。

工具续调和历史改写仍须等待已确认的目标。若候选可能已发送且缺少确认结果，网关保留待核查状态。缺少回退进度的旧待核查记录继续按原保护处理。

暂停、恢复和撤销作用于上游账号池。更换 Key 后须在模型服务中采用新账号版本并重新验证发布。发布的账号身份、端点和协议不会随 Provider 编辑自动改变。

每个模型的 API Key 账号池支持固定顺序、依次轮换和按权重分配。权重为 1–1000 的整数，默认 1。轮换和权重作用于新轮次的候选计划。暂停、撤销、达到本机并发或每分钟限制、冷却中、正在探测恢复或已确认硬预算耗尽的账号暂不参与分配。冷却到期后，账号可参与排序以取得恢复探测机会。取得探测名额后，其他请求的排序会避开该账号上需要恢复探测的目标，直到探测完成。允许凭据或模型权限回退时，已确认被拒绝的账号也暂不参与分配。发送前重新检查当前授权、额度和容量。轮换状态按发布版本持久保存，原轮次重试沿用已保存的候选顺序。

同会话后续轮次默认独立分配。启用「优先沿用」后，网关会先尝试同模型最近一次成功提交输出的可用账号。「固定账号」按逻辑模型沿用该账号版本。发布新的上游模型后，原账号版本仍在账号池且通过验证时，新轮次可使用新模型。更换供应商或移除原账号版本后，已固定的会话会停止，用户可以恢复原账号或开启新会话。子服务命中固定账号后，达到本机限额或收到明确上游失败时，父服务也会停止回退。请求详情显示实际使用的账号及选择策略。

额度策略可优先用即将重置的额度、剩余比例较高的账号，或重置前平均每小时剩余额度比例较高的账号。每小时比例用剩余比例除以到重置的小时数。多个有效窗口共同约束一个账号时，剩余比例和每小时比例分别取最低值。若可用候选中有账号缺少该策略所需的新鲜额度数据，同组候选按配置顺序尝试。已确认耗尽的额度仍会拦截发送，恢复条件取决于上游。

OpenRouter 账号可在供应商详情读取密钥支出预算和当前生效的剩余预算。路由会检查官方响应列出的密钥、成员和工作区预算。同一官方连接的同一凭据在默认连接和账号池中共用已确认的预算限制和恢复探测。额度未知、已过期或已越过重置时间时，排序忽略该额度。所有账号池策略和使用默认凭据的模型服务都在发送前检查已确认的预算约束。固定账号的同会话请求和工具续调会保留原账号，预算耗尽时等待刷新或重置。 [OpenRouter 当前密钥接口](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key)

额度读取由用户在账户面板发起，模型请求使用现有快照。默认连接和账号池引用同一份已保存的凭据、并使用同一官方额度来源时，共用正在执行的刷新和 10 秒重试间隔。快照按发起读取的账号版本保存。新读取完成后，同凭据其他入口的旧快照标为过期并退出排序，原读数保留供核查。新结果缺字段或读取失败时，排序仍以当前可用证据为准。

每个账号先通过自己的官方快照确认预算范围。刷新完成后，服务在保存结果时重新核对账号版本、授权状态与额度插件启用状态。读取期间已被撤销或替换的账号，其结果会被丢弃。只有官方身份信息能确认同一工作区成员与护栏，或同一工作区预算时，账号才共享最新有效的额度观测。密钥预算始终按密钥隔离。平台余额和支出预算在账户面板独立展示。

供应商的「上游账号」、默认连接的「连接与额度」和发布预览使用同一份路由额度判断。账号启用状态、余额快照是否已读取、额度暂停与恢复探测分别显示。刷新账户用量后可核对新的路由状态；查看状态本身不会发送上游请求。

OpenRouter 的余额快照过期、刷新失败或响应缺少预算字段时，缺少当前证据的金额停止参与排序。已确认耗尽的账号仍退出轮换和权重分配，发送前继续拦截。明确的新余额、官方完整列表确认限制已移除，或已知重置点可以解除对应约束。没有重置时间的预算等待明确的新证据。更换凭据或额度来源重新启用后，按新的身份与快照核对。

跨过已知重置点后，第一条可发送的正常模型请求用来探测恢复。即使首个请求在额度快照过期后才到，仍按已知重置点处理。同一密钥、同一成员预算或同一工作区预算下的服务共享探测状态。一个请求涉及多个重置范围时，会在发送前一起预留探测。并发请求按原策略尝试其他候选，固定的工具续调和重放会提示稍后重试。固定入口实际执行额度探测时，等待上游响应头和首次有效输出均受发布时限约束。非流式回复通过校验，或流式回复收到完整的协议结束事件后，同一重置范围恢复普通路由。流式探测的占用覆盖完整交付窗口。限流按上游 Retry-After 记录冷却，已发送的探测超时或取消后等待策略冷却。发布前预览区分等待探测、探测中、通过和探测冷却。

已保存连接的额度刷新将发送约束和共享归属写入本机数据库。服务重启后按对应凭据和重置点恢复约束。升级时，旧账号池记录经过账号版本和官方连接核对后归入同一凭据。已通过的探测继续生效，已设置的冷却保留原结束时间。重启时仍在执行的探测进入策略冷却，到期后由同组首条可发送的正常请求重新探测。账户金额快照随进程重建。 [OpenRouter 密钥重置规则](https://openrouter.ai/docs/api/api-reference/api-keys/create-keys)

### DeepSeek 和 Kimi 余额

官方 DeepSeek 接口用 HTTP 402 表示余额不足，余额查询中的 `is_available` 表示当前可用性。官方 Kimi 接口在 429 响应的错误类型为 `exceeded_current_quota_error` 时表示余额、额度或账号不可用。余额查询成功且 `available_balance` 为零或负数时，也会暂停该凭据。普通 429 继续按限流策略冷却。 [DeepSeek 错误码](https://api-docs.deepseek.com/quick_start/error_codes/) · [DeepSeek 余额接口](https://api-docs.deepseek.com/api/get-user-balance/) · [Kimi 错误码](https://platform.kimi.ai/docs/api/errors) · [Kimi 余额接口](https://platform.kimi.ai/docs/api/balance)

默认连接与账号池共用同一官方连接和凭据的暂停状态。余额无法确认或刷新失败时，已确认的暂停跨重启保留。新鲜的官方余额结果显示可用后，先放行一条探测请求，其他请求按已发布的策略尝试备用候选。探测收到有效模型输出后恢复普通路由，再次收到明确的余额或额度拒绝时恢复暂停。现金余额不参与周期余量排序。

### MiniMax M Plan 订阅

在供应商中选择 **MiniMax M Plan**，填写国际站控制台签发的 `sk-cp-` 订阅 Key。预设支持 Messages、Chat Completions 和 Responses，模型服务的连接验证使用各账号自己的 Key。把其他订阅 Key 登记到同一供应商的上游账号池后，可使用固定顺序、轮换、权重或额度策略。该连接供本机 Agent 调用。官方端点和签发方式见 [MiniMax M Plan 接入文档](https://platform.minimax.io/docs/m-plan/other-tools)。

`MiniMax-M3.1-Flash` 会运行内置推理。网关为该模型使用低推理强度，遵守请求输出上限，将文本与标准工具调用返回给客户端，保留实际用量。推理占用输出预算。 [MiniMax Messages 参数说明](https://platform.minimax.io/docs/api-reference/text-chat-anthropic)

在供应商详情刷新每个订阅账号，可读取文本模型的 5 小时与 7 天用量。两个窗口都有当前余量时，按较紧的窗口比较。缺少一个窗口或该窗口已过期时，单个窗口的正余量不足以参加额度排序。重置时间和每小时余量策略也需要两个窗口相应的时间数据。

任一窗口确认订阅内额度耗尽后，模型服务暂停向该凭据发送请求，避免超额请求自动扣除已购积分。同一份已保存凭据的 Messages、Chat Completions 和 Responses 入口共享暂停和恢复探测。已确认的耗尽状态跨服务重启保留。缺失或过期的窗口数据会保留之前的耗尽状态，刷新取得该窗口的有效余量可解除对应暂停。所有已知耗尽的窗口到期后，同一凭据一次只允许一个恢复探测。探测失败后进入冷却；没有重置时间的窗口需要刷新确认余量。同一订阅签发的多个 Key 可能共享额度。 [MiniMax 用量规则](https://platform.minimax.io/docs/m-plan/usage-rules)

同一账号的当前凭据只会同时发起一次额度刷新。MiniMax 明确拒绝授权时，界面提示在官方控制台核对订阅 Key。2062 显示「订阅状态待确认」，可核对订阅后稍后重试。更换 Key 后可以立即刷新新账号版本，旧版本的结果和失败提示随原版本隔离。更新账号池中的 Key 后，需要重新验证并发布引用它的模型服务。 [MiniMax 错误码说明](https://platform.minimax.io/docs/api-reference/errorcode)

## 固定入口与历史

入口与本机认证按 Agent 配置绑定；发布服务新版本不改文件、不轮换本机认证。服务定义、发布快照、安装目录和请求路由分别保存。Provider 修改不会自动改变已发布快照，需重新验证并发布服务。每次调用记录服务版本、默认 / 指定选择及实际 Provider / 模型；界面默认目标不等于所有会话已切换。

沿用 [动态路由](dynamic-routing.md) 的可信 Session、连续历史、签名历史与工具轮次约束。无法确认新轮次或历史不可移植时保持旧目标；没有旧租约的工具续调拒绝。0.1.6 将传输大小和上下文预算分开。官方 `api.deepseek.com` 的已知 V4 Pro / Flash 模型使用随包固定版本的官方分词数据；输入包含系统提示、消息、工具定义与工具选择，再加 10% + 256 + 每条消息 16 Token 的协议余量，另预留请求输出上限。其他来源使用明确标记的文本估算（ASCII 约每 3 字符一个 Token，其他字符每字符 2 Token，加相同余量）。完整协议计数仍为估算，不宣称与供应商最终计费一致。32 MiB 传输上限独立保留。

真实超限返回 Messages 兼容的 `invalid_request_error` / `context_length_exceeded`，英文可识别语义与中文提示同时保留，上游同类拒绝也规范化，使 OpenCode 能识别上下文错误并进入自身压缩流程。不会把字节数直接当作 Token 数。观测保存计数方法、输入估算、输出预留和入口窗口。

OpenCode 旧 32K 目录需同步一次才能采用新的能力声明。目录同步沿用原 Provider 分组键和仍存在的逻辑模型别名，保存用户选择；新绑定及新加密备份仍通过受控事务建立，旧绑定继续可恢复。日常策略与上游切换无需再次同步。

## 兼容、迁移与恢复

schema 5 增加持久候选计划、尝试日志和共享冷却；schema 4 升级前保存 `local-agent.pre-routing-policy-v4.sqlite3` 一致性备份（0600）。尝试日志上限 32768，冷却作用域上限 4096，达到容量时拒绝新增。schema 4 新增模型服务定义、不可变发布版本、绑定目录、已解析目标表及轮次服务元数据。schema 3 升级前使用 SQLite `VACUUM INTO` 保存 `local-agent.pre-model-services-v3.sqlite3`，0600 权限并核对数据库版本与一致性；schema 2 原升级备份继续保留。升级不自动迁移或清理用户的 Agent 配置。

旧固定路由与 0.1.4 动态绑定继续可用。已有连接在用户确认切换前保持原样，切换到模型服务或直接 Provider 都走原生配置事务。旧 pending、原加密备份及恢复在连接详情保留。OpenCode 保留其他目录与用户模型覆盖配置；删除服务前应移除相关目录引用，或恢复到该服务接入前的配置。恢复先生成预览，核对配置 revision 后才能覆盖；已有权限、MCP 及无关配置通过原生适配保留。已有 Claude 模型白名单不允许新目录时拒绝接入，不扩大白名单。

已有模型服务在显式发布账号池之前继续使用默认凭据。要恢复单连接，在服务编辑器移除账号池，按需恢复原路由策略，再用当前默认凭据验证并发布新版本。现有 Agent 配置、旧发布版本和请求记录继续保留。已绑定账号的工具续调仍按原轮次处理，遇到已撤销的账号时拒绝发送。

发布历史、路由版本、切换与轮次各有既有有界容量，到达上限拒绝新增，历史引用不自动驱逐。服务发布版本上限 4096。降级不能直接替换旧服务或修改 user_version；须先保存新增数据并按升级备份和原生加密备份恢复。

## 接口与职责

受控 IPC 增加 `get_model_services`、`save_model_service`、`delete_model_service`、`prepare_model_service_connection`。本机管理服务对应 `/api/model-services`、`/api/model-services/{id}/delete`、`/api/model-service-connections`；继续核验管理令牌、Host 和 Origin。原生写入仍经配置事务 apply / cancel / restore。

认证网关 `/gateway/{binding}/v1/models` 返回已安装目录和能力，支持有界分页；它不会暴露 Provider 凭据。目录发现和原生配置注入互补，不能假定所有客户端会实时刷新 `/models`。

界面：`src/features/model-services/`；桌面适配：`src-tauri/src/commands/model_services.rs`；管理 API：`crates/local-agent-service/src/model_services.rs`；核心：`crates/local-agent-core/src/model_services.rs`。未增加 crate 或第二套配置存储；0.1.6 新增锁定的 `tokenizers` 依赖及压缩的 MIT 官方分词数据，来源、提交和摘要保存在 `crates/local-agent-service/assets/tokenizers/manifest.json`，运行时不下载。
