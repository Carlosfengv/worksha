# 插件标准与准入规则

插件中心按完整业务功能组织入口，界面中的来源只有“系统自带”和“用户上传”，由宿主确定，不能由插件自行声明。模型服务、任务、项目作为一级业务功能；功能场景用于查找，不暴露技术运行预设。上传扩展按已声明的能力进入相应场景，同一扩展可以服务多个场景。

## 业务功能与界面契约

业务插件登记实际页面入口、可执行操作、数据与授权条件，以及完整生命周期接入状态。描述只能覆盖当前界面和后台已提供的能力，只读观测不能描述为管理、启动或执行。

业务插件的启停同时控制页面与深链、相关后台入口和归属它的只读支撑，不能只隐藏菜单。9 个系统业务插件与 16 个只读支撑已纳入同一依赖图；开关只展示实际运行状态。运行任务或请求未结束时拒绝变更，不自动终止 Agent；旧运行代不能发布新结果。细粒度领域契约、Agent 运行适配和外部 SDK 的其余迁移仍按后续阶段实施，既定需求不缩减。

系统自带和用户上传均提供启用、停用和卸载。必需依赖先展示连带启停范围并由后台再次验证；可选能力缺失只影响相关操作，在确认中说明，不能把所有功能一并停用。停用 Providers 会连带停用模型服务、Agents 和任务；停用 Sessions 会连带停用项目、MCP 和总览。停用项目只影响项目功能和任务中的已有项目选择，不阻止任务使用本机目录。

卸载保留历史数据与用户配置，移除功能注册、准入和所属资源，记录跨重启保持。系统代码是签名应用的一部分，不直接改写应用包；重新安装使用应用随附的可信版本。插件中心、设置、授权撤销和未知操作恢复是常驻宿主能力，不能由业务插件卸载。启用消费者可恢复必需依赖，停用过的其他消费者不自动恢复。

插件通过宿主领域接口访问共享数据，不能提交 SQL 或自行迁移宿主表。格式升级、数据归属、回执保留与备份边界见 [数据库设计](database-design.md)。插件卸载不等于清空历史数据；查不到已过保留范围的回执也不能解释为未执行。

当前说明和操作定义见 [system-features.ts](../src/features/plugins/system-features.ts)，入口从应用已注册页面生成；[功能对照](plugin-functions.md)列出入口、操作与使用条件。未实现或未验证的操作不能标为可用。

## 插件身份和清单

用户上传 `.laplug` 包，使用现有统一 `manifestVersion: 1` 清单、宿主 API `1.0.0` 与 Wasm ABI `local-agent:plugin@1.0.0`。清单声明唯一 ID、发布者、语义版本、宿主兼容范围、运行方式、能力、依赖和权限。完整类型与 JSON Schema 由 Rust 生成，见 [清单契约](../contracts/plugins/manifest.schema.json) 和 [SDK](../sdk/plugins/README.md)。

ID 位于发布者命名空间，保留的系统标识不能覆盖。未知字段、未支持能力或权限、不兼容版本、无效依赖和相互矛盾的能力组合均拒绝。安装渠道不赋予额外能力；用户上传不能伪装为系统插件。

系统自带模块由应用构建与分发，在同一能力宿主中声明版本、实例、依赖及资源归属，接受依赖和生命周期检查。其受信任的编译内执行方式不向上传包开放；用户上传包仍使用受限运行环境和独立资源授权。

## 包准入

| 检查 | 规则 |
| --- | --- |
| 包结构 | ZIP 格式；压缩最多 32 MiB，解压总量最多 128 MiB，最多 1000 个普通文件；Wasm 最多 32 MiB |
| 路径 | 安全 ASCII 相对路径；拒绝链接、目录项、重复路径与大小写冲突 |
| 完整性 | `files.json` 精确登记载荷 SHA-256；安装时重新核对摘要，上传检查与安装绑定同一包身份 |
| 发布者 | Ed25519 签名必须有效；首次安装需用户明确核对并信任公钥，更换已信任公钥必须重新处理，签名不冒充组织身份认证 |
| 开发包 | 只有显式插件开发模式允许既有规则支持的未签名包，界面明确提示；数据来源与纯路由策略始终要求签名 |
| 能力与权限 | 仅接受宿主已实现的有限能力与对应权限，按能力派发到相应执行与授权流程，不扩大权限 |
| 安装容量与冲突 | 共用现有跨能力安装身份、版本、发布者、容量及暂存预算检查 |

上传检查只读取和暂存包，不安装、不执行插件、不授予文件、连接或账户访问。应用根据校验后的清单识别能力，用户使用一个上传入口。失败保持明确原因，不能把失败显示为已安装或运行中。

## 安装、启用和资源配置

用户确认发布者及权限后，界面顺序执行安装和启用。安装失败不继续启用；启用失败保留已安装事实，并显示待启用或异常，供用户核查。结果未知时读取实际状态，不自动重放写入。

启用经过准备、激活和健康检查；预检阶段不能访问资源。需要文件或账户时，由用户选择和授权具体资源；模型服务策略还需明确绑定服务。安装或启用不能自动取得文件、网络、账户、模型配置修改权限，也不能被显示为已经有数据。

权限通过宿主提供的有限接口执行。Wasm 没有任意文件、进程、网络或凭据访问；网络请求由宿主验证目标并注入凭据。MCP 本机程序仍适用其独立、明确的启动与权限边界，不能用统一界面掩盖执行差异。

## 状态与生命周期

插件中心区分待启用、运行中、已停用、待授权、异常、未知与过期状态。来源是安装渠道，不能代替功能或运行状态。开关读取实际状态；来源、连接和数据新鲜度在详情中展示。

停用、卸载、撤权和换版本会使相应资源引用、缓存与旧结果失效。初始化失败不得遗留注册；迟到结果不能写入新代。上传插件卸载回收受管副本，系统插件卸载移除功能注册与所属资源并持久保存移除状态。两者都保留历史数据、用户所选原文件与账户；重新安装不自动恢复已撤销的读取授权。不受本次变更影响的请求导出视图保持可用，停用请求插件时回收其导出引用。

开发者打包、签名、离线检查、示例及各能力的完整契约见 [SDK](../sdk/plugins/README.md)。该规范整理并采用现有宿主强制执行的规则，准入检查始终在本地服务执行。
